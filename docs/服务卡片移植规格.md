## 一、三个规格分别是什么

### 1.1 逐字段对照表

| 项 | 标准（`schedule_widget_info.xml`） | 小（`_small.xml`） | 大（`_large.xml`） |
|---|---|---|---|
| Provider 类 | `ScheduleWidgetProvider` | `ScheduleWidgetProviderSmall`（空子类） | `ScheduleWidgetProviderLarge`（空子类） |
| `minWidth` | **250dp** | **110dp** | **250dp** |
| `minHeight` | **110dp** | **110dp** | **250dp** |
| `targetCellWidth` | **4** | **2** | **4** |
| `targetCellHeight` | **2** | **2** | **4** |
| `maxResizeWidth` | **320dp** | 未声明 | 未声明 |
| `maxResizeHeight` | **250dp** | 未声明 | 未声明 |
| `updatePeriodMillis` | **1800000**（30 分钟） | **1800000** | **1800000** |
| `initialLayout` | `@layout/widget_schedule_list` | 同左 | 同左 |
| `resizeMode` | `horizontal\|vertical` | `horizontal\|vertical` | `horizontal\|vertical` |
| `widgetCategory` | `home_screen` | `home_screen` | `home_screen` |
| `description` | `@string/widget_description` | 同左 | 同左 |

- `@string/widget_description` = **「在桌面查看今日与本周课程」**（`res/values/strings.xml:4`）。
- 三个 Provider 共用**同一个布局、同一套数据逻辑**：`ScheduleWidgetProviderSmall` / `...Large` 只是空子类，`onUpdate` / `onReceive` / `refreshAll` 全在基类，靠 `ListView` 自适应高度（源码注释原文：「基类 + 多个空子类分别对应不同尺寸规格，ListView 自动适配高度」）。

### 1.2 各自显示什么内容

**三个规格显示的内容完全相同**：`WidgetDataSource.load()` 返回的 `todayCourses`（**今日**课程），只是可见行数不同（`ListView` 高度不同 → 能露出几行）。

- ⚠️ **不是本周**。`WidgetSchedule` 里有 `weekCourses`「本周全部课程，用于大尺寸小部件展示周课表」（`WidgetDataSource.kt:13`），`RoomWidgetDataSource` 也确实查了它（`getWeekCoursesSync()`），但**全工程再无任何使用者**（grep `weekCourses` 只有定义与赋值两处）。所以「本周」目前只活在 `widget_description` 文案里，是**未实现的承诺**。移植时要么照抄"今日"、要么把这个坑补上。
- 大规格（4x4）与标准（4x2）的差别仅在高度：`ListView` 的 `layout_weight=1` 撑满，能滚出更多行。

### 1.3 尺寸换算（`70n-30` 公式）

Android 官方格子换算：**n 格 = `70n - 30` dp**（1 格 70dp，两端各扣 15dp 内边距），反推 `n = (size + 30) / 70`：

| 规格 | minWidth 反推 | minHeight 反推 | 与 `targetCell*` 是否自洽 |
|---|---|---|---|
| 标准 | (250+30)/70 = **4 格** | (110+30)/70 = **2 格** | ✅ 4×2 |
| 小 | (110+30)/70 = **2 格** | (110+30)/70 = **2 格** | ✅ 2×2 |
| 大 | (250+30)/70 = **4 格** | (250+30)/70 = **4 格** | ✅ 4×4 |

`maxResizeWidth/Height`（仅标准规格）换成格：320dp→5 格、250dp→4 格，即源码注释「支持拉伸到 5x4」。

> ⚠️ **鸿蒙的 `supportDimensions` 是「行*列」**，与 Android 的 `targetCellWidth×targetCellHeight`（列×行）**正好转置**。
> 官方定义：`2*4：表示2行4列的八宫格`。所以 Android 标准规格 4 列 × 2 行 → 鸿蒙 **`2*4`**；小 → `2*2`；大 → `4*4`。这是移植时最容易写错的一处。

### 2.4 课程色条怎么画的

Android 侧（`ScheduleWidgetService.getViewAt`）：

```kotlin
views.setInt(R.id.widget_item_bar, "setBackgroundColor", item.color)
```

- 本质是「一个 `4dp` 宽的 `TextView`，用 `setBackgroundColor` 刷背景色」——因为 **RemoteViews 只支持反射调用有限的方法**（`setInt(viewId, "setBackgroundColor", argb)` 是白名单之一），不能设 drawable、不能设 tint、不能画 shape。
- 颜色来自 `CourseColor.of(c.name).toArgb()`：**按课程名 hashCode 从 16 色调色板取色**（同名永远同色），`toArgb()` 把 Compose `Color` 转成 `Int`。
- 色条同时被 `minHeight=42dp` 保底（课程名 + 时间 + 教师三行文字比 42dp 高，所以实际几乎恒等于「行内容高度」，`match_parent` 上下各让出 6dp 的 `paddingTop/Bottom`）。

## 三、数据是怎么喂进去的

### 3.1 `WidgetDataSource.kt`（抽象层）

```kotlin
data class WidgetSchedule(
    val currentWeek: Int,             // 当前第几周（1 起）
    val todayCourses: List<Course>,   // 今天的课程，按节次排序
    val weekCourses: List<Course>,    // 本周全部课程（⚠️ 从未被使用）
)

interface WidgetDataSource {
    fun load(day: DayOfWeek, firstWeekMonday: LocalDate): WidgetSchedule
}
```

- 目的：**小部件与存储解耦**（注释原文：「由数据层（Room）实现；小部件只依赖本接口，便于适配多种规格」）。
- 注入方式：`GltuScheduleApp.onCreate()` → `WidgetDataHolder.source = container.widgetDataSource`；`AppContainer.widgetDataSource = RoomWidgetDataSource(scheduleRepository)`（lazy）。

### 3.2 `RoomWidgetDataSource.kt`（Room 实现）

```kotlin
override fun load(day: DayOfWeek, firstWeekMonday: LocalDate): WidgetSchedule {
    val today = LocalDate.now()
    val week = computeCurrentWeek(firstWeekMonday, today)                 // 当前周次，最小 1
    val todayCourses = repository.getDayCoursesSync(day)                  // 按星期几查
        .filter { it.occursOnWeek(week) }                                 // 再按显式周次集合过滤
    val weekCourses = repository.getWeekCoursesSync()
    return WidgetSchedule(week, todayCourses, weekCourses)
}
// computeCurrentWeek = ChronoUnit.WEEKS.between(第一周周一, 本周周一) + 1，coerceAtLeast(1)
```

- 查询是**同步**的（`getDayCoursesSync` → `courseDao.getByDaySync`），注释明确「RemoteViewsFactory.onDataSetChanged 运行在 Binder 线程池，天然满足后台线程要求」。

### 3.4 显示的是「今日」还是「本周」？为空显示什么？

- **今日**（`todayCourses`），三个规格都一样。`weekCourses` 查了但没人用（见 §1.2）。
- 为空/异常时显示**一条灰色占位行**（`#FF9E9E9E`，不是空白）：
  - 被屏蔽：「今天是周末」/「假期：XX」 + 「课程已屏蔽，好好休息 🎉」
  - 数据源未注入：「点击进入 App 并导入课表」 + 「支持手动添加 / 分享码 / 教务系统导入」
  - 今天确实没课：「今天没有课」 + 「享受你的休息日」
- 布局里的 `widget_empty`（「暂无课程」）实际不会显示。

### 3.5 有没有跳过节假日/调休的逻辑？——有，且是本小部件最"聪明"的一段

`HolidayManager.isBlocked()`（`HolidayManager.kt:232-253`）的判定顺序：

1. **调休补班日优先**：`holidays.any { it.type == MAKEUP && it.contains(date) }` → **直接返回 false（照常上课）**，「即使是周末也照常上课」。
2. `settings.weekend && isWeekend(date)` → 屏蔽（`block_weekend` 默认 **false**）。
3. 遍历假期：`STATUTORY` 看 `settings.statutory`（默认 true）、`SCHOOL` 看 `settings.school`（默认 true）、`USER_DEFINED` 跟随 `statutory`、`MAKEUP` 永远不屏蔽。

- 数据来源：内置 GLTU 校历假期 + 内置法定节假日（未联网同步时）+ 联网同步结果（有则覆盖法定部分）+ 用户自定义。
- 标题里也用同一套判定：`holidayNameOf() != null && isBlocked()` → 显示「日期 · 假期名」，否则显示「第 N 周 · 日期」。
- ⚠️ **一个逻辑缺口**（鸿蒙版已有更好的实现，见 §6.5）：被判定为调休补班日时，小部件仍然按**今天本身的星期几**去查课（`DayOfWeek.from(today)`），所以 2026-10-10（周六，补 10/7 周二的课）小部件显示的是「周六的课」（通常是空的），而不是周二那天的课。鸿蒙侧 `Index.ets` 用 `MakeupResolver.effectiveDate()` 做了正确映射，卡片应当跟随。

## 四、刷新时机

### 4.1 `refreshAll` / `notifyAppWidgetViewDataChanged` 的调用点

| 位置 | 触发场景 |
|---|---|
| `ui/edit/EditCourseViewModel.kt:127` | 手动添加/编辑课程保存成功后（`syncDownstream()`：重排提醒 + 刷新小部件） |
| `ui/schedule/ScheduleViewModel.kt:410` | 删除课程后（`syncDownstream()`，注释说明「否则已删课程的闹钟还在会继续响」） |
| `ui/share/CourseShareScreen.kt:100` | 分享码导入课表成功后（`clearCourses + upsertCourses` 之后） |
| `ui/import/WebImportScreen.kt:488` | 教务系统网页导入成功后 |

四处都是同一个模式：**课程数据变更 → 重排上课提醒 → `ScheduleWidgetProvider.refreshAll(ctx)`**。

`refreshAll()` 内部：动态取三个子类的 `ComponentName`（`ScheduleWidgetProvider` / `...Small` / `...Large`），对拿到的每个 `appWidgetId` 调 `updateWidget()`。

`updateWidget()` 的动作序列（**关键**）：

```kotlin
views.setRemoteAdapter(R.id.widget_list, svcIntent)      // 绑定 RemoteViewsService
views.setEmptyView(R.id.widget_list, R.id.widget_empty)
views.setTextViewText(R.id.widget_title, buildTitle(context))   // 标题
views.setOnClickPendingIntent(R.id.widget_title_bar, openPi)    // 点标题栏 → 打开 App
views.setOnClickPendingIntent(R.id.widget_empty, openPi)
mgr.updateAppWidget(id, views)
mgr.notifyAppWidgetViewDataChanged(id, R.id.widget_list) // ⚠️ 必须显式调
```

源码注释原文解释了为什么两件事都要做：
> 「`updateAppWidget` 不会触发 `RemoteViewsFactory.onDataSetChanged()`，必须显式通知，否则 30 分钟的定时刷新只更新标题、课程列表还是旧的。」

### 4.2 `updatePeriodMillis` = **1800000 ms = 30 分钟**（三个规格一致）

这是 Android 允许的最小值；系统在 `onUpdate` 里跑一次 `updateWidget`，但**列表数据仍要靠 `notifyAppWidgetViewDataChanged`**（见上）。设备休眠时系统会推迟。

### 4.3 `ACTION_REFRESH` 是死代码

```kotlin
const val ACTION_REFRESH = "com.ltyksa.gltuschedule.widget.REFRESH"
override fun onReceive(...) { if (intent.action == ACTION_REFRESH) { ...对所有规格重跑 onUpdate } }
```

全仓库（含构建产物）搜 `ACTION_REFRESH` / `sendBroadcast`：**只有声明和处理，没有任何地方发送过这个广播**。它是为"外部触发刷新"预留的钩子，目前没人用。

### 4.4 点击小部件跳哪

```kotlin
val openIntent = Intent().apply {
    setClassName(context, "com.ltyksa.gltuschedule.MainActivity")
    flags = Intent.FLAG_ACTIVITY_NEW_TASK
}
PendingIntent.getActivity(context, id /* requestCode = appWidgetId */, openIntent,
    FLAG_UPDATE_CURRENT or FLAG_IMMUTABLE)
```

- 目标：`com.ltyksa.gltuschedule.MainActivity`（硬编码字符串，不是 `MainActivity::class.java`）。
- 绑定到 `widget_title_bar`（整条标题栏）和 `widget_empty`。
- **列表行不响应点击**（没有 `setOnClickFillInIntent`）。
- `requestCode = appWidgetId`，保证多实例的 PendingIntent 不互相覆盖。

## 五、UI 细节

### 5.1 每一行显示什么

| 位置 | 内容 | 格式/取值 |
|---|---|---|
| 主标题行 | **课程名** | `c.name`；颜色=课程色；14sp bold；单行省略号 |
| 副标题行 | **时间 · 地点** | `"${start.startTime}–${end.endTime} · ${Classroom.shortLabel(location)}"`；时间如 `08:20–09:40`；地点为空则 `地点待定`；两者用一个**英文空格 + `·` + 空格**连接；11sp `#CCFFFFFF` |
| 第三行 | **教师** | `c.teacher`；**空字符串时整行 GONE**；11sp `#99FFFFFF` |
| 右侧 | **节次** | `"第1-2节"`（`rangeLabel`：`a==b` → `第3节`，否则 `第1-2节`）；11sp `#CCFFFFFF` |
| 最左 | 色条 | 4dp 宽，课程色 |

**地点是"短标签"不是全称**：`Classroom.shortLabel()` 把「雁山校区 3220（阶7教室）」压成「旅博楼 3220（阶7教室)」（剥掉"XX校区"前缀，按 4 位房号规则推出楼栋名）。全称版本是 `detailLabel()`（「雁山校区 · 旅博楼 2 楼 · 3220（阶7教室）」），**小部件不用它**。

### 5.2 空状态文案原文（逐字）

| 场景 | 第一行 | 第二行 |
|---|---|---|
| 周末被屏蔽 | `今天是周末` | `课程已屏蔽，好好休息 🎉` |
| 假期被屏蔽 | `假期：{假期名}`（如 `假期：校运会`） | `课程已屏蔽，好好休息 🎉` |
| 无数据源 | `点击进入 App 并导入课表` | `支持手动添加 / 分享码 / 教务系统导入` |
| 今天没课 | `今天没有课` | `享受你的休息日` |
| 布局里的空视图（实际不显示） | `暂无课程` | — |

### 5.3 标题文案原文（`buildTitle()`）

```kotlin
dateText = "${today.monthValue}月${today.dayOfMonth}日 " + weekdayCn(today.dayOfWeek)   // 例："10月29日 周四"
holiday  = HolidayManager.holidayNameOf(context, today)
if (holiday != null && HolidayManager.isBlocked(context, today)) "$dateText · $holiday"   // "10月29日 周四 · 校运会"
else                                                            "第 ${SemesterStore.currentWeek(context)} 周 · $dateText"  // "第 8 周 · 10月29日 周四"
```

- 周几映射：`周一/周二/周三/周四/周五/周六/周日`。
- 布局文件里的静态默认值 `@string/widget_title_today` = **「今日课程」**，运行时必被覆盖（只在预览/异常时可见）。
- 注意格式细节：`第 ` 和 ` 周` **前后都有空格**，`月` `日` 后紧跟一个空格再接周几，分隔符是 ` · `（前后带空格）。

## 六、鸿蒙服务卡片的移植规格

### 6.0 总体映射（一张表看懂）

| Android | 鸿蒙 | 说明 |
|---|---|---|
| `AppWidgetProvider`（3 个空子类） | `FormExtensionAbility`（1 个）+ `form_config.json` 里 3 个 `forms` 条目 | 一个扩展能力可挂最多 16 张卡片 |

### 6.2 `module.json5` 要加什么

在现有 `extensionAbilities` 数组（已有 `EntryBackupAbility`）后追加：

```json5
{
  "name": "EntryFormAbility",
  "srcEntry": "./ets/scheduleformability/EntryFormAbility.ets",
  "label": "$string:EntryFormAbility_label",
  "description": "$string:EntryFormAbility_desc",
  "type": "form",
  "metadata": [
    {
      "name": "ohos.extension.form",          // 固定字符串，不能改
      "resource": "$profile:form_config"      // → resources/base/profile/form_config.json
    }
  ]
}
```

要点：
- `metadata.name` 必须是固定字符串 **`ohos.extension.form`**。
- 不需要 `exported: true`（模板不写，默认 false；卡片由系统桌面作为使用方拉起，不靠导出）。
- 不需要额外权限；**不要**用 `call` 事件（那才需要 `ohos.permission.KEEP_BACKGROUND_RUNNING`）。
- `deviceTypes` 已含 phone/tablet/2in1，无需改。


字段依据（官方 `arkts-ui-widget-configuration.md` + DevEco 模板实测）：

- 一个应用**最多 16 个 form**；`name` ≤127 字节且**不要用资源引用**（五元组之一，用资源会在资源变动后导致卡片被系统删除）；`displayName` ≤30 字节（中文约 10 字）；`description` ≤255 字节。
- **`window.designWidth/autoDesignWidth` 只对 JS 卡片生效**，ArkTS 卡片写了也会被忽略 → 建议直接省略（DevEco 模板保留只是历史包袱）。
- `colorMode` **API 20 起已废弃**，卡片主题统一跟随系统 → 省略。我们的卡片用字面量深色，两种模式下长得一样。
- `updateDuration`：单位 **30 分钟**，`0` = 不生效；**它优先级高于 `scheduledUpdateTime`**（同时配置时定点刷新不执行）。所以上面只写 `updateDuration`，不写 `scheduledUpdateTime`。
- `resizable` / `groupId`（API 20+）可替代 Android 的 `resizeMode`：若想让**一张卡片**在 2*2 / 2*4 / 4*4 之间拖拽缩放（最接近 Android 那种自由拉伸），可只保留**一个** form 条目：
  ```json5
  "supportDimensions": ["2*2", "2*4", "4*4"],
  "defaultDimension": "2*4",
  "resizable": true,
  "groupId": "gltuSchedule"
  ```
  卡片内用 `onSizeChanged` 收到的 dimension 决定显示几行。**代价**：卡片中心只出现一张卡片，且三档之间是"跳变"而非 Android 的连续像素拉伸。要严格复刻"三个规格"就用上面三个条目的写法。
- `formConfigAbility: "ability://EntryAbility"` = 桌面长按卡片「编辑」时拉起的页面（Android 侧无对应物，可换成你自己的设置页 URI，如 `ability://EntryAbility`）。

### 6.5 `ScheduleCardData.ets`（数据构建，可直接照写）

```ts
/**
 * GltuSchedule · 鸿蒙版 —— 服务卡片数据构建
 * 对应 Android：
 *   ScheduleWidgetService.ScheduleWidgetFactory.loadTodayCourses()  （行数据）
 *   ScheduleWidgetProvider.buildTitle()                             （标题）
 *
 * ⚠️ 本文件只被 EntryFormAbility（卡片提供方进程）引用，卡片 UI 不引用它，
 *    因此可以自由使用 relationalStore / preferences。
 */
import { preferences, relationalStore } from '@kit.ArkData';
import { common } from '@kit.AbilityKit';
import { DateUtil } from '../data/DateUtil';
import { GltuTimeTable } from '../data/TimeSlot';
import { Classroom } from '../data/Classroom';
import { BlockSettings, HolidayManager } from '../data/Holiday';
import { MakeupResolver } from '../data/MakeupRule';
import { Course, Semester } from '../model/Course';

/** 卡片里的一行（对应 Android 的 widget_course_item + WidgetItem） */
export interface CardCourseItem {
  name: string;     // 课程名 / 提示语
  meta: string;     // "08:20–09:40 · 旅博楼 3220"（U+2013，与 Android 一致）
  teacher: string;  // 空串 = 不渲染这一行（= Android 的 View.GONE）
  period: string;   // "第1-2节"
  color: string;    // "#E57373"
}

/** 推给卡片的数据，key 必须和卡片里 @LocalStorageProp 的名字完全一致 */
export interface CardPayload {
  title: string;
  items: CardCourseItem[];
}

const DB_NAME: string = 'gltu_schedule.db';
const PREF_NAME: string = 'gltu_prefs';
const TABLE: string = 'courses';
const COLUMNS: string[] = ['id', 'name', 'teacher', 'location', 'day_of_week', 'start_index',
  'end_index', 'start_week', 'end_week', 'odd_even', 'category', 'credit', 'weeks_text', 'weeks_csv'];
const GRAY: string = '#9E9E9E';                    // = Android 的 0xFF9E9E9E

/**
 * 卡片专用调色板：与 Android `CourseColor.palette` 逐色对齐。
 * ⚠️ 鸿蒙现有 `data/CourseColor.ets` 用的是另一套更深沉的 16 色（#4E6E9E…），
 *    直接拿来当深色卡片上的**文字色**会看不清。哈希算法两边一致（都是 h*31+code），
 *    所以下标相同、只是色值不同 —— 卡片要用 Android 这套浅色。
 */
const CARD_PALETTE: string[] = [
  '#E57373', '#F06292', '#BA68C8', '#9575CD', '#7986CB', '#64B5F6', '#4FC3F7', '#4DD0E1',
  '#4DB6AC', '#81C784', '#AED581', '#DCE775', '#FFD54F', '#FFB74D', '#FF8A65', '#A1887F'
];

function cardColorOf(name: string): string {
  if (name === undefined || name === null || name.length === 0) {
    return CARD_PALETTE[0];
  }
  let h: number = 0;
  for (let i = 0; i < name.length; i++) {
    h = (h * 31 + name.charCodeAt(i)) | 0;         // = Java/Kotlin String.hashCode()
  }
  return CARD_PALETTE[((h % 16) + 16) % 16];
}

let rdb: relationalStore.RdbStore | undefined = undefined;
let pref: preferences.Preferences | undefined = undefined;

/** 卡片提供方是独立进程，必须自己初始化；onAddForm 是同步方法，所以用同步 API */
export function ensureInit(context: common.Context): void {
  if (rdb === undefined) {
    rdb = relationalStore.getRdbStoreSync(context,
      { name: DB_NAME, securityLevel: relationalStore.SecurityLevel.S1 });   // API 24+
  }
  if (pref === undefined) {
    pref = preferences.getPreferencesSync(context, { name: PREF_NAME });      // API 10+
  }
}

function queryAllCourses(): Course[] {
  const list: Course[] = [];
  if (rdb === undefined) {
    return list;
  }
  const p = new relationalStore.RdbPredicates(TABLE);
  p.orderByAsc('day_of_week');
  p.orderByAsc('start_index');
  const rs = rdb.querySync(p, COLUMNS);                                       // API 12+
  while (rs.goToNextRow()) {
    const c = new Course();
    c.id = rs.getLong(rs.getColumnIndex('id'));
    c.name = rs.getString(rs.getColumnIndex('name'));
    c.teacher = rs.getString(rs.getColumnIndex('teacher'));
    c.location = rs.getString(rs.getColumnIndex('location'));
    c.dayOfWeek = rs.getLong(rs.getColumnIndex('day_of_week'));
    c.startIndex = rs.getLong(rs.getColumnIndex('start_index'));
    c.endIndex = rs.getLong(rs.getColumnIndex('end_index'));
    c.startWeek = rs.getLong(rs.getColumnIndex('start_week'));
    c.endWeek = rs.getLong(rs.getColumnIndex('end_week'));
    c.oddEven = rs.getLong(rs.getColumnIndex('odd_even'));
    c.weeksText = rs.getString(rs.getColumnIndex('weeks_text'));
    const csv = rs.getString(rs.getColumnIndex('weeks_csv'));
    if (csv !== undefined && csv !== null && csv.length > 0) {
      const parts = csv.split(',');
      const weeks: number[] = [];
      for (let i = 0; i < parts.length; i++) {
        const n = parseInt(parts[i].trim(), 10);
        if (!isNaN(n) && weeks.indexOf(n) < 0) {
          weeks.push(n);
        }
      }
      weeks.sort((a: number, b: number) => a - b);
      c.weeks = weeks;
    }
    list.push(c);
  }
  rs.close();
  return list;
}

export class ScheduleCardData {

  /** 一行能放几门课：由卡片规格决定（对应 Android 里 ListView 高度决定可见行数） */
  static rowCap(dimension: number): number {
    // formInfo.FormDimension: Dimension_1_2=1, Dimension_2_2=2, Dimension_2_4=3, Dimension_4_4=4,
    //                         DIMENSION_1_1=6, DIMENSION_6_4=7
    if (dimension === 2) { return 1; }   // 2*2 ≈ Android 110×110dp
    if (dimension === 3) { return 3; }   // 2*4 ≈ Android 250×110dp
    if (dimension === 4) { return 6; }   // 4*4 ≈ Android 250×250dp
    if (dimension === 7) { return 9; }   // 6*4
    return 3;
  }

  static build(context: common.Context, dimension: number): CardPayload {
    ensureInit(context);
    const today: number = DateUtil.today();
    const firstMonday: number = pref!.getSync('first_monday', DateUtil.mondayOf(today)) as number;

    const holiday: HolidayManager = new HolidayManager();
    const settings: BlockSettings = new BlockSettings(
      pref!.getSync('block_statutory', true) as boolean,
      pref!.getSync('block_school', true) as boolean,
      pref!.getSync('block_weekend', false) as boolean
    );

    // ---------- 标题：等价于 ScheduleWidgetProvider.buildTitle() ----------
    const dateText: string =
      `${DateUtil.label(today)} ${DateUtil.weekdayLabel(DateUtil.weekday(today))}`;   // "10月29日 周四"
    const holidayName: string = holiday.holidayNameOf(today);
    const blocked: boolean = holiday.isBlocked(today, settings);
    const title: string = (holidayName.length > 0 && blocked)
      ? `${dateText} · ${holidayName}`                                   // "10月29日 周四 · 校运会"
      : `第 ${Semester.currentWeek(firstMonday)} 周 · ${dateText}`;       // "第 8 周 · 10月29日 周四"

    // ---------- 分支①：节假日/周末屏蔽 ----------
    if (blocked) {
      const name: string = holidayName.length > 0
        ? holidayName
        : (HolidayManager.isWeekend(today) ? '周末' : '假期');
      return {
        title: title,
        items: [{
          name: name === '周末' ? '今天是周末' : `假期：${name}`,
          meta: '课程已屏蔽，好好休息 🎉',
          teacher: '', period: '', color: GRAY
        }]
      };
    }

    const all: Course[] = queryAllCourses();

    // ---------- 分支②：课表为空（≈ Android 的数据源未就绪） ----------
    if (all.length === 0) {
      return {
        title: title,
        items: [{
          name: '点击进入 App 并导入课表',
          meta: '支持手动添加 / 分享码 / 教务系统导入',
          teacher: '', period: '', color: GRAY
        }]
      };
    }

    // ---------- 分支③：调休日 → 上"被替代那一天"的课 ----------
    // Android 版这里是用「今天本身的星期几」查课（调休日会查错），鸿蒙跟随 Index.ets 的正确做法。
    const overrides = MakeupResolver.decodeOverrides(
      pref!.getSync('makeup_overrides', '') as string);
    const rules = MakeupResolver.resolve(holiday.allHolidays(), overrides);
    const effDate: number = MakeupResolver.effectiveDate(rules, today);
    const effWeekday: number = DateUtil.weekday(effDate);
    const effWeek: number = Semester.weekOf(firstMonday, effDate);

    const courses: Course[] = all.filter((c: Course) =>
      c.dayOfWeek === effWeekday && c.occursOnWeek(effWeek));
    courses.sort((a: Course, b: Course) => a.startIndex - b.startIndex);

    // ---------- 分支④：今天没有课 ----------
    if (courses.length === 0) {
      return {
        title: title,
        items: [{ name: '今天没有课', meta: '享受你的休息日', teacher: '', period: '', color: GRAY }]
      };
    }

    // ---------- 分支⑤：正常行 ----------
    const cap: number = ScheduleCardData.rowCap(dimension);
    const items: CardCourseItem[] = [];
    const n: number = Math.min(courses.length, cap);
    for (let i = 0; i < n; i++) {
      const c: Course = courses[i];
      const start = GltuTimeTable.byIndex(c.startIndex);
      const end = GltuTimeTable.byIndex(c.endIndex);
      const time: string = (start !== undefined && end !== undefined)
        ? `${start.startTime}–${end.endTime}` : '';                 // U+2013 EN DASH
      const shortLoc: string = Classroom.shortLabel(c.location);
      const place: string = shortLoc.length > 0 ? shortLoc : '地点待定';
      const meta: string = (time.length > 0 ? `${time} · ${place}` : place);
      items.push({
        name: c.name,
        meta: meta,
        teacher: c.teacher,
        period: GltuTimeTable.rangeLabel(c.startIndex, c.endIndex),
        color: cardColorOf(c.name)
      });
    }
    return { title: title, items: items };
  }
}
```

要点与坑：

1. **`onAddForm` 是同步方法**（签名 `onAddForm(want: Want): formBindingData.FormBindingData`），不能 `await`。若工程 `compatibleSdkVersion < 24`（没有 `getRdbStoreSync`），改成两步：`onAddForm` 先返回占位数据（`{title:'正在加载…', items:[]}`），紧接着异步查库再 `formProvider.updateForm(formId, ...)`。
2. 卡片提供方进程与主进程**同沙箱**（官方进程模型原文：「两个进程之间内存隔离，但是共享相同的文件沙箱」），所以能直接读同一份 `gltu_schedule.db` / `gltu_prefs`。**只读**，别在卡片进程写库。
3. `FormExtensionAbility` **空闲 10 秒会被系统回收**（SDK 原话："The formExtensionAbility is cleared after 10 seconds of inactivity"），所以这条链路必须轻、快。
4. `CourseStore`（`database/CourseStore.ets`）是异步 `init()` 的单例，**在卡片进程里没被初始化过**，不要复用；上面这段自带同步初始化。
5. 颜色：**必须用 Android 那套浅色调色板**（`CARD_PALETTE`）。鸿蒙现有的 `CourseColor.of()` 返回 `#4E6E9E` 这类深色，画在 `#E6263040` 深底上当文字色会糊成一团。
6. 每行内容与 Android 逐字一致：空态四套文案、`地点待定`、`第1-2节`、`08:20–09:40`（en dash）全部照抄。

### 6.6 `FormRegistry.ets`（formId 登记，兜底刷新用）

```ts
/**
 * formId → 规格(dimension) 登记表。
 * 用途：卡片被回收后 onUpdateForm 只有 formId，需要知道它是什么规格；
 *      以及 App 主进程想做"定点推送"时的兜底路径（见 §6.8 方案 B）。
 */
import { preferences } from '@kit.ArkData';
import { common } from '@kit.AbilityKit';

const FORM_PREF: string = 'gltu_forms';
const KEY_IDS: string = 'ids';
const DEFAULT_DIM: number = 3;   // 2*4

function p(context: common.Context): preferences.Preferences {
  return preferences.getPreferencesSync(context, { name: FORM_PREF });
}

export class FormRegistry {
  static remember(context: common.Context, formId: string, dimension: number): void {
    const pref = p(context);
    pref.putSync(`dim_${formId}`, dimension);
    const raw = pref.getSync(KEY_IDS, '') as string;
    const ids: string[] = raw.length > 0 ? raw.split(',') : [];
    if (ids.indexOf(formId) < 0) {
      ids.push(formId);
      pref.putSync(KEY_IDS, ids.join(','));
    }
    pref.flush();
  }

  static dimensionOf(context: common.Context, formId: string): number {
    return p(context).getSync(`dim_${formId}`, DEFAULT_DIM) as number;
  }

  static forget(context: common.Context, formId: string): void {
    const pref = p(context);
    pref.deleteSync(`dim_${formId}`);
    const raw = pref.getSync(KEY_IDS, '') as string;
    const ids: string[] = raw.length > 0
      ? raw.split(',').filter((x: string) => x !== formId) : [];
    pref.putSync(KEY_IDS, ids.join(','));
    pref.flush();
  }

  static all(context: common.Context): string[] {
    const raw = p(context).getSync(KEY_IDS, '') as string;
    return raw.length > 0 ? raw.split(',') : [];
  }
}
```

### 6.7 `EntryFormAbility.ets`（可直接照写）

```ts
/**
 * GltuSchedule · 鸿蒙版 —— 服务卡片生命周期
 * 对应 Android：ScheduleWidgetProvider（onUpdate / onReceive）+ ScheduleWidgetService
 */
import { formBindingData, FormExtensionAbility, formInfo, formProvider } from '@kit.FormKit';
import { Want } from '@kit.AbilityKit';
import { BusinessError } from '@kit.BasicServicesKit';
import { hilog } from '@kit.PerformanceAnalysisKit';
import { CardPayload, ScheduleCardData } from './ScheduleCardData';
import { FormRegistry } from './FormRegistry';

const DOMAIN: number = 0x0000;
const TAG: string = 'GLTUForm';

export default class EntryFormAbility extends FormExtensionAbility {

  /** 卡片被添加到桌面：必须同步返回首屏数据 */
  onAddForm(want: Want): formBindingData.FormBindingData {
    const formId: string = want.parameters?.[formInfo.FormParam.IDENTITY_KEY] as string;
    const dimension: number = want.parameters?.[formInfo.FormParam.DIMENSION_KEY] as number;
    FormRegistry.remember(this.context, formId, dimension);
    hilog.info(DOMAIN, TAG, 'onAddForm formId=%{public}s dim=%{public}d', formId, dimension);
    return formBindingData.createFormBindingData(this.payload(dimension));
  }

  /** 定时刷新（updateDuration）、定点刷新、系统请求刷新都走这里 */
  onUpdateForm(formId: string, wantParams?: Record<string, Object>): void {
    this.push(formId);
  }

  /** 卡片内 postCardAction({action:'message'}) 触发（可做"手动刷新"按钮） */
  onFormEvent(formId: string, message: string): void {
    hilog.info(DOMAIN, TAG, 'onFormEvent %{public}s', message);
    this.push(formId);
  }

  /** 卡片尺寸被拖拽改变（API 20+） */
  onSizeChanged(formId: string, newDimension: formInfo.FormDimension,
                newRect: formInfo.Rect): void {
    FormRegistry.remember(this.context, formId, newDimension);
    this.push(formId);
  }

  onRemoveForm(formId: string): void {
    FormRegistry.forget(this.context, formId);
  }

  onCastToNormalForm(formId: string): void {}

  onAcquireFormState(want: Want): formInfo.FormState {
    return formInfo.FormState.READY;
  }

  private payload(dimension: number): CardPayload {
    return ScheduleCardData.build(this.context, dimension);
  }

  private push(formId: string): void {
    const dimension: number = FormRegistry.dimensionOf(this.context, formId);
    const data = formBindingData.createFormBindingData(this.payload(dimension));
    formProvider.updateForm(formId, data).catch((err: BusinessError) => {
      hilog.error(DOMAIN, TAG, 'updateForm 失败 code=%{public}d msg=%{public}s',
        err.code, err.message);
    });
  }
}
```

> `want.parameters?.[formInfo.FormParam.IDENTITY_KEY]` 就是 formId（键名 `ohos.extra.param.key.form_identity`）；
> `DIMENSION_KEY`（`ohos.extra.param.key.form_dimension`）取值即 `formInfo.FormDimension` 枚举值。

### 6.8 `formProvider.updateForm()` 的调用时机（鸿蒙没有 BroadcastReceiver 怎么办）

Android 是「谁改了数据，谁 `sendBroadcast`/直接调 `refreshAll`」；鸿蒙没有这个机制，等价的触发面有三条，**建议全用**：

**A. 定时刷新（替代 `updatePeriodMillis=1800000`）**
`form_config.json` 里 `updateEnabled: true` + `updateDuration: 1` → 系统每 30 分钟回调一次 `onUpdateForm`，在里面 `updateForm`。
- 硬约束：**每张卡片每天最多 50 次**定时触发（超了当天不再触发，0 点重置）。`updateDuration: 1` = 48 次/天，**已经贴着配额**，所以**不要再叠加 `setFormNextRefreshTime`**（最短 5 分钟，会挤爆配额）。
- 首次刷新最多有 30 分钟偏差；卡片不可见时只记录、可见时才真正刷新。
- 想要「零点换天」不需要定点刷新：30 分钟粒度自然会跨过零点。若要更省电，`updateDuration: 2`（1 小时，24 次/天）。

**B. 数据变更主动推（替代 `ScheduleWidgetProvider.refreshAll`）**
课程增删改/导入/设置变更处，调 **`formProvider.reloadAllForms(context)`**（API 22+；本项目 compatibleSdkVersion 26.0.0，可用）：

```ts
// 任意页面里，替换掉 Android 的 ScheduleWidgetProvider.refreshAll(ctx)
import { common } from '@kit.AbilityKit';
import { formProvider } from '@kit.FormKit';

const ctx = this.getUIContext().getHostContext() as common.UIAbilityContext;
formProvider.reloadAllForms(ctx)                 // 刷新本应用全部卡片
  .then((n: number) => console.info(`reloadAllForms: ${n}`))
  .catch((e: BusinessError) => console.error(JSON.stringify(e)));

// 或只刷某一个规格（moduleName / abilityName / formName）
formProvider.reloadForms(ctx, 'entry', 'EntryFormAbility', 'scheduleCardMedium');
```
- 语义：**主进程通知 FormExtension 进程**去批量跑 `onUpdateForm`，正好等价于 Android 的 `refreshAll`（provider 内部自取数据），**不需要自己存 formId**。
- 只能在 **UIAbility** 里调用（参数要 `UIAbilityContext`）。

需要落地的调用点（对齐 Android 的 4 处 + 补 Android 漏掉的一处）：

| 鸿蒙位置 | 场景 | Android 对应 |
|---|---|---|
| `pages/EditCoursePage.ets`（保存/删除课程后） | 课程增删改 | `EditCourseViewModel.kt:127`、`ScheduleViewModel.kt:410` |
| `pages/SharePage.ets`（导入分享码后） | 课表替换/追加 | `CourseShareScreen.kt:100` |
| `pages/WebImportPage.ets`（导入成功后） | 教务系统导入 | `WebImportScreen.kt:488` |
| `pages/SettingsPage.ets`（改第一周周一 / 三个屏蔽开关 / 调休覆盖后） | **Android 漏了**：改设置后小部件标题（第 N 周）与屏蔽状态要等 30 分钟才更新 | 无 |

**C. 卡片内点击触发（替代 `ACTION_REFRESH` 那段死代码）**
卡片里放个刷新按钮 / 点标题时发 message：
```ts
postCardAction(this, { action: 'message', params: { msg: 'refresh' } });
```
→ 触发 `onFormEvent(formId, message)` → `updateForm`。
也可以不做按钮，让任何 `postCardAction` 的 message 都触发一次重算。

**兜底方案（不吃 reloadForms 的 API 22 要求）**：用 §6.6 的 `FormRegistry` 存下所有 formId，在 App 主进程直接推：
```ts
for (const id of FormRegistry.all(ctx)) {
  formProvider.updateForm(id, formBindingData.createFormBindingData(payloadOf(id)));
}
```
但这要求主进程也能算出数据（主进程有 `StoreHolder`，本来就初始化过），且 `reloadForms` 更省事 —— **优先用 B**。

### 6.9 三个 ArkTS 卡片页面（`WidgetCard*.ets`）

`WidgetCardSmall.ets` / `WidgetCardMedium.ets` / `WidgetCardLarge.ets` **内容完全相同**（只有 `ROW_MAX` 常量不同），因为 Android 三个规格也共用一套布局。以 2*4 为例（可直接照写；另两个把 `ROW_MAX` 改成 1 / 6，文件名与 struct 名相应替换）：

```ts
/**
 * GltuSchedule · 鸿蒙版 —— 今日课程卡片（2*4，≈ Android 4x2 标准小部件）
 * 对应 Android 的 RemoteViews 布局：widget_schedule_list.xml + widget_course_item.xml
 *
 * ⚠️ 卡片 UI 跑在系统"卡片渲染服务进程"里：
 *    不能读数据库/首选项、不能 import 未标注"支持在ArkTS卡片中使用"的模块、
 *    不能用 setTimeout。所有内容都由 EntryFormAbility 通过 formBindingData 推来。
 */

interface CardCourseItem {
  name: string;
  meta: string;
  teacher: string;
  period: string;
  color: string;
}

const ROW_MAX: number = 3;                            // = ScheduleCardData.rowCap(2*4)

let cardStorage = new LocalStorage();                 // 卡片数据容器（每个卡片实例独立）

@Entry(cardStorage)
@Component
struct WidgetCardMedium {
  // key 必须与 createFormBindingData 里的字段名一致
  @LocalStorageProp('title') title: string = '今日课程';
  @LocalStorageProp('items') items: CardCourseItem[] = [];

  build() {
    Column() {
      // ===== 标题栏（widget_title_bar + widget_title）=====
      Row() {
        Text(this.title)
          .fontSize(14)                               // 14sp
          .fontWeight(FontWeight.Bold)
          .fontColor('#FFFFFF')
          .maxLines(1)
          .textOverflow({ overflow: TextOverflow.Ellipsis })
          .layoutWeight(1)
      }
      .width('100%')
      .padding(10)                                    // padding="10dp"
      .onClick(() => {
        // = Android 的 setOnClickPendingIntent(title_bar, PendingIntent→MainActivity)
        postCardAction(this, {
          action: 'router',
          bundleName: 'com.ltyksa.gltuschedule',
          moduleName: 'entry',
          abilityName: 'EntryAbility',
          params: { from: 'form' }
        });
      })

      // ===== 课程列表（widget_list）=====
      Column() {
        ForEach(this.items, (item: CardCourseItem) => {
          this.CourseRow(item);
        }, (item: CardCourseItem, index: number) => `${index}-${item.name}-${item.period}`)
      }
      .width('100%')
      .layoutWeight(1)                                // = layout_weight="1"
      .alignItems(HorizontalAlign.Start)
    }
    .width('100%')
    .height('100%')
    .backgroundColor('#E6263040')                     // = @drawable/widget_background 的 solid
    .borderRadius(16)                                 // = corners radius 16dp
    .alignItems(HorizontalAlign.Start)
  }

  /** 一行课程（widget_course_item.xml） */
  @Builder
  CourseRow(item: CardCourseItem) {
    Row() {
      // 色条：widget_item_bar（4dp 宽、minHeight 42dp、运行时设课色）
      Column()
        .width(4)
        .height(42)
        .backgroundColor(item.color)
        .borderRadius(2)

      // 中间三行（LinearLayout weight=1 + paddingStart 10dp + paddingEnd 6dp）
      Column() {
        Text(item.name)
          .fontSize(14)
          .fontWeight(FontWeight.Bold)
          .fontColor(item.color)                      // 课程名 = 课色
          .maxLines(1)
          .textOverflow({ overflow: TextOverflow.Ellipsis })   // singleLine + ellipsize=end
          .width('100%')

        Text(item.meta)
          .fontSize(11)
          .fontColor('#CCFFFFFF')
          .maxLines(1)
          .textOverflow({ overflow: TextOverflow.Ellipsis })
          .width('100%')

        if (item.teacher.length > 0) {                // = View.GONE / VISIBLE
          Text(item.teacher)
            .fontSize(11)
            .fontColor('#99FFFFFF')
            .maxLines(1)
            .textOverflow({ overflow: TextOverflow.Ellipsis })
            .width('100%')
        }
      }
      .layoutWeight(1)                                // = layout_weight="1"
      .alignItems(HorizontalAlign.Start)
      .padding({ left: 10, right: 6 })

      // 右侧节次（widget_item_period）
      Text(item.period)
        .fontSize(11)
        .fontColor('#CCFFFFFF')
        .maxLines(1)
        .padding({ right: 10, top: 2 })
    }
    .width('100%')
    .padding({ top: 6, bottom: 6 })                   // paddingTop/Bottom 6dp
    .alignItems(VerticalAlign.Top)
  }
}
```

**逐条对照与注意点**

| Android | ArkTS | 备注 |
|---|---|---|
| `LinearLayout orientation=vertical` | `Column()` | — |
| `layout_weight="1"` | `.layoutWeight(1)` | — |
| `FrameLayout`（标题栏） | `Row()` | 单子元素容器，Row/Stack 都行 |
| `ListView` + `RemoteViewsFactory` | `Column()` + `ForEach` | 见下方"为什么不用 List" |
| `TextView` | `Text()` | — |
| `singleLine + ellipsize=end` | `.maxLines(1).textOverflow({overflow: TextOverflow.Ellipsis})` | — |
| `View.GONE` | `if (...) { }` 条件渲染 | ArkTS 无 visibility:Gone 的等价写法（有 `.visibility(Visibility.None)`，但条件渲染更省内存） |
| `dp / sp` | `vp / fp`（数值直接照抄） | ArkTS 里 `.fontSize(14)` 默认单位 fp；`.width(4)` 默认 vp |
| 色条 `match_parent` + `minHeight=42dp` | `.height(42)` 固定 | ⚠️ ArkTS 里在 `wrap_content` 的 Row 内用 `.height('100%')` 会量成 0，**不要写百分百**；要真正随行高伸展就把行高固定（如 `52`）并让色条 `height(40)`，或用 `Flex({alignItems: ItemAlign.Stretch})` + 固定行高 |
| `setOnClickPendingIntent` | `.onClick(() => postCardAction(this, {...}))` | `postCardAction` **只能在卡片组件的 onClick 里调**；Android 侧列表行本来不可点，这里保持一致的"只有标题栏可点" |
| 深色圆角底 | `.backgroundColor('#E6263040').borderRadius(16)` | 卡片本身有系统背板，根容器铺满即可盖住；想要"透明背板"要 `transparencyEnabled`（系统应用/需申请） |

**为什么不用 `List` 组件**：ArkTS 卡片允许 `List`/`ListItem`（SDK 的 `ets/component/form_config.json` 里有），但卡片高度是固定的，长列表要靠滑动，容易和桌面手势打架（官方只禁止"左右滑动控件"，竖向可滚但体验差）。Android 侧 `ListView` 也是"高度内显示、多了滚动"，行为类似，但**卡片上建议直接按 `dimension` 截断行数**（`ScheduleCardData.rowCap`），超出部分不加提示或加一条「还有 N 门课」（Android 没有这条，属可选增强）。

**三份卡片文件重复代码怎么办**：可以抽一个 `pages/CardCommon.ets`（只放 `interface` + `@Builder` 函数，**零 import**），三个卡片相对路径 import 它 —— 卡片支持相对 import 本模块文件，但**被 import 的文件也必须满足卡片能力约束**（不能引 ArkData/网络等）。若不确定，就三份各写一遍最安全。

**卡片可用的组件（API 26 SDK 实测白名单，共 38 个）**：
`Badge, Blank, Button, Canvas, Checkbox, CheckboxGroup, Circle, Column, Counter, DataPanel, Divider, Ellipse, Flex, Gauge, GridCol, GridRow, Image, Line, List, ListItem, LoadingProgress, Marquee, Path, Polygon, Polyline, Progress, QRCode, Radio, Rating, Rect, RelativeContainer, Row, Shape, Slider, Span, Stack, Text, Toggle`
**不可用**：`Scroll, Grid, GridItem, Swiper, Tabs, TextInput, TextArea, Search, Web, XComponent, Video, Navigation, Refresh, NavigationBar, 自定义弹窗…`

### 6.10 鸿蒙卡片的限制（移植时必须知道的硬约束）

1. **卡片 UI 在系统公共的"卡片渲染服务进程"里跑**，与自己的应用进程隔离：**读不到数据库、读不到首选项、发不了网络请求**。所有数据必须由 `FormExtensionAbility` 通过 `formBindingData.createFormBindingData()` 推过去 —— 这正好对应 Android 的 `RemoteViewsFactory` 在服务侧把数据"烘焙"成 RemoteViews 的思路。
2. **数据通道**：卡片里用 `@LocalStorageProp('key')` 单向接收，key 必须与 `createFormBindingData(obj)` 的字段名一致；**不支持 `@LocalStorageLink`**。传数组/对象可以（`items: CardCourseItem[]` 是官方常见写法），框架会序列化后交给卡片；若某版本上数组拿不到，退化成「传 JSON 字符串 + 卡片内 `JSON.parse`」即可（卡片允许跑逻辑代码）。
3. **单次数据量**：API 20+ 走共享内存，总量 ≤10MB、图片 ≤20 张；API ≤19 图片 ≤5 张、单张 ≤2MB。我们的数据只有几十字节，无压力。
4. **只允许 import 标注了"支持在 ArkTS 卡片中使用"的模块**；支持 HAR 静态包，**不支持 HSP**；不支持 native/so。
5. **不支持 `setTimeout`**（卡片里不能做定时器/倒计时）；不支持左右滑动的控件；不支持断点调试 / Hot Reload / 极速预览。
6. **尺寸是枚举**：`1*2 / 2*2 / 2*4 / 4*4 / 6*4`（手表另有 `2*3 / 3*3`）。Android 那种"随便拉成 5x4"在鸿蒙要靠 API 20+ 的 `resizable: true` + 在 `supportDimensions` 列出的规格间跳变。
7. **定时刷新配额**：每张卡片每天 ≤50 次；`updateDuration` 与 `setFormNextRefreshTime` 共用这个额度；卡片不可见时不真正刷新。Android 的 `updatePeriodMillis` 也有 30 分钟下限和设备休眠延迟，量级一致。
8. **`FormExtensionAbility` 空闲 10 秒被回收**，且**不能引用** `particleAbility`、`audio`、`camera`、`media`、`backgroundTaskManager`（引了可能直接崩）→ 生命周期回调里别做重活、别开长任务。
9. **卡片不是页面**：不能响应返回键、不能弹自定义对话框、不能 `router.pushUrl`；跳应用只能用 `postCardAction` 的 `router`（等价 `Intent + setClassName + FLAG_ACTIVITY_NEW_TASK`）。
10. **五元组**（bundleName + moduleName + abilityName + formName + dimension）变了，桌面上已添加的卡片会被系统删除。所以 `form_config.json` 的 `name` **不要引用资源文件**。

### 6.11 已知差异 / 需要决策的点（汇总）

| # | 事项 | 建议 |
|---|---|---|
| 1 | `weekCourses` 在 Android 从未被用 | 鸿蒙侧不必实现；若要在大卡片上真做"本周课表"，那是一次新功能（Android 也没有） |
| 2 | 调休补班日 Android 查错星期几 | 鸿蒙按 `MakeupResolver.effectiveDate()` 做对（§6.5 分支③），并在标题里可选加「· 补周二课」 |
