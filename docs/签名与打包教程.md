# 鸿蒙版签名与打包 · 一步步教程

> 环境：DevEco Studio **26.0.0.851** · 工程 `D:\dshcj\GltuSchedule-HarmonyOS`

---

## 第 0 步 · 先搞清楚现在为什么签不了

我查了工程当前状态：

```
build-profile.json5  →  "signingConfigs": []        ← 空的，所以出的是 unsigned
signing/             →  app-chain.cer / chainA.cer / chainB.cer / profile.p7b
                        ↑ 这是 OpenHarmony 默认测试证书链（证书里写的是 O=OpenHarmony）
                        ↑ 而且**没有配对的私钥 .p12**，签不了
SDK 里的 OpenHarmony.p12 → 也是测试密钥，只能签 OpenHarmony 开发板
```

**结论**：那套文件是模板/测试用的，**华为商用 HarmonyOS NEXT 手机不认**。
必须用**你自己的华为开发者证书**重新签。

---

## 第 1 步 · 搞清楚签名需要哪三样东西

签名 = 用私钥给安装包盖章，让手机能验证「这个包确实是你发的、没被改过」。

| 文件 | 是什么 | 类比 |
|---|---|---|
| **`.p12`** | 私钥库（要密码） | 你的**印章** |
| **`.cer`** | 证书（公钥 + 你的身份信息） | 印章的**备案证明** |
| **`.p7b`** | Profile 授权文件 | **准予发布某个包的批文**（里面绑定了包名 + 证书 + 应用 ID） |

**三个必须互相匹配**：
- `.cer` 必须是由 `.p12` 里的私钥对应的公钥签发的
- `.p7b` 里记录的证书必须就是那个 `.cer`
- `.p7b` 里记录的包名必须等于 `AppScope/app.json5` 里的 `bundleName`

任何一个对不上，签名都会失败。

## 第 2 步 · 准备华为开发者账号

1. 打开 <https://developer.huawei.com/consumer/cn/>
2. 注册账号 → **实名认证**（个人开发者免费，需要身份证）
3. 认证通过后才能用签名功能

> 没有这个账号，下面一步都做不了。

---

## 第 3 步 · 路线 A：自动签名（先把 App 装到自己手机上）

这条路线最省事，DevEco 全自动帮你生成三样东西。

1. 打开 DevEco Studio
2. 菜单 `File` → `Open...` → 选 `D:\dshcj\GltuSchedule-HarmonyOS`
   - ⚠️ 要选**工程根目录**（有 `build-profile.json5` 的那一层），不是 `entry`
3. 等右下角进度条跑完（首次会下载依赖，几分钟）
4. **右上角登录华为账号**（点头像 → Sign In）
5. 菜单 `File` → `Project Structure...`（快捷键 `Ctrl+Alt+Shift+S`）
6. 左侧选 `Project` → `Signing Configs`
7. 勾选 **`Automatically generate signature`**
   - 会弹窗问是否同意，点 `Agree`
   - 然后它自动去 AGC 建应用、生成证书、下载 Profile，转圈几十秒
8. 完成后点 `Apply` → `OK`
9. 打开 `build-profile.json5`，`signingConfigs` 应该不再是空数组了 ✓
10. 顶部设备栏选你的手机（USB 连接 + 开发者模式 + USB 调试）
11. 点绿色 ▶ **Run** —— 直接装上手机

**这条路生成的是「调试证书」**，Profile 里绑定了你手机的 UDID，
**只能装到你自己的设备上，不能上架**。

> 想同时验证能不能出正式包，可以接着走路线 B。

## 第 4 步 · 路线 B：正式发布签名（上架 AGC 用）

### 4.1 先在 AGC 建应用

1. 打开 <https://developer.huawei.com/consumer/cn/service/josp/agc/index.html>
2. `我的应用` → `新建应用`
3. **包名必须逐字填 `com.ltyksa.gltuschedule`**（和 `app.json5` 里一致，填错后面全废）
4. 应用名 `GLTU 课表`，分类选「教育 → 学习工具」
5. 建完记下**应用 ID（App ID）**，后面要用

### 4.2 生成密钥和 CSR

1. DevEco 菜单 `Build` → `Generate Key and CSR...`
2. 第一次会让你新建一个密钥库：
   - `Key store file`：选个安全的地方存，例如 `D:\certs\gltu.p12`
   - 设两个密码（keystore 密码 / key 密码），**记牢，丢了只能重新签**
   - `Key alias`：例如 `gltu`（自己起，后面签名要用）
   - 算法选 `ECC` / `NIST-P-256`
3. 生成后会得到一个 **`.csr`** 文件（证书签名请求）

### 4.3 在 AGC 申请发布证书

1. AGC → `证书、App ID和Profile` → `证书` 页 → `新增证书`
2. 证书类型选 **`发布证书`**
3. 上传刚才的 `.csr`
4. 下载得到 **`.cer`**（例如 `gltu-release.cer`）

> ⚠️ 发布证书一个账号**最多 2 个**，别乱建。

### 4.4 在 AGC 申请发布 Profile

1. AGC → `证书、App ID和Profile` → `Profile` 页 → `新增 Profile`
2. 类型选 **`发布`**
3. 选刚建的应用（`com.ltyksa.gltuschedule`）
4. 选刚下载的发布证书
5. 申请 → 下载得到 **`.p7b`**（例如 `gltu-release.p7b`）

> 发布 Profile **不需要填设备 UDID**（调试 Profile 才要）。

### 4.5 在 DevEco 里配置手动签名

1. `File` → `Project Structure...` → `Signing Configs`
2. **取消勾选** `Automatically generate signature`
3. 填：

| 字段 | 填什么 |
|---|---|
| `Store file` | `D:\certs\gltu.p12` |
| `Store password` | 你设的 keystore 密码 |
| `Key alias` | `gltu` |
| `Key password` | 你设的 key 密码 |
| `Sign alg` | `SHA256withECDSA` |
| `Profile file` | `gltu-release.p7b` |
| `Certpath` | `gltu-release.cer` |

4. `Apply` → `OK`

### 4.6 切到 release 并打包

1. 左下角（或 `Build` → `Build Variants`）把 build mode 从 `debug` 切成 **`release`**
2. 菜单 `Build` → `Build Hap(s)/APP(s)` → **`Build APP(s)`**
3. 产物在：

```
GltuSchedule-HarmonyOS/build/outputs/default/GltuSchedule-default-signed.app
                                                          ^^^^^^^^^^^^^
                                                   这个 .app 才是传 AGC 的
```

> ⚠️ **`.hap` 和 `.app` 不是一回事**：
> `.hap` 是单个模块（手机安装用），`.app` 是整包（应用市场收这个）。

### 4.7 上传

AGC → 你的应用 → `版本管理` → `创建版本` → 上传那个 `.app` →
填版本号 `0.14.0` → 提交审核。

## 第 5 步 · 以后想省事：命令行签名

只要你手上有 `.p12` + `.cer` + `.p7b`，就不用每次开 IDE 点来点去。
我已经写好脚本了：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
D:\dshcj\tools\sign-hap.ps1 `
  -Keystore   D:\certs\gltu.p12 `
  -KeystorePwd '你的keystore密码' `
  -KeyAlias   gltu `
  -KeyPwd     '你的key密码' `
  -CertFile   D:\certs\gltu-release.cer `
  -ProfileFile D:\certs\gltu-release.p7b
```

脚本会：
1. 自动找最新的 unsigned HAP
2. 调 `hap-sign-tool.jar` 签名
3. **自动 verify 一遍**（验签失败会明确告诉你别上传）
4. 打印大小和 SHA-256

> 完整流程：`.\build.ps1` 出 unsigned HAP → `sign-hap.ps1` 签名 → 得到 signed HAP。
> 上架用的 `.app` 还是得在 DevEco 里 `Build APP(s)`（命令行也能做，但配置更绕）。

## 附 · 常见报错对照

| 报错 | 原因 | 怎么修 |
|---|---|---|
| `Check param num failed` | 参数没给全 | 对照第 5 步的命令，别漏 |
| `Signature verification failed` | 签名算法不匹配 | ECC 密钥用 `SHA256withECDSA`，RSA 用 `SHA256withRSA` |
| `keyAlias not found` | alias 写错 | 用 `keytool -list -keystore x.p12` 看真实 alias |
| `profile is invalid` | p7b 和证书/包名对不上 | 确认 p7b 是在 AGC 用**同一个证书 + 同一个包名**申请的 |
| 装到手机报 `install failed code 9568289` | 用了调试证书但设备不在 Profile 里 | 换发布证书，或把设备 UDID 加进调试 Profile |
| DevEco 里自动签名转圈很久然后失败 | 包名在 AGC 已被别人占用 | 换个 `bundleName`（但那样就和安卓不一致了） |
| `hvigor ERROR: spawn java ENOENT` | 没配 JAVA_HOME | 设 `JAVA_HOME=D:\DevEco Studio\jbr`（`build.ps1` 已经帮你设了） |

## 一句话总结

```
没有华为开发者账号  →  什么都做不了，先去实名认证
自动签名            →  能装自己手机，不能上架
AGC 建应用 + 申请证书/Profile  →  DevEco 手动配置  →  Build APP(s)  →  得到 .app  →  传 AGC
```
