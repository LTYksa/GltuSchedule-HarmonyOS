## 三、上架前你需要自己做的

### 1. 签名（必做，我做不了）
HAP 目前是 **unsigned**，无法安装也无法上架。在 DevEco Studio 里：

```
File → Project Structure → Signing Configs → 勾选 Automatically generate signature
```

需要登录**华为开发者账号**（要实名认证，个人开发者免费）。
签好后 `Build → Build Hap(s)/APP(s) → Build APP(s)` 出 **`.app`** 文件，
上架 AGC 用的是 `.app` 不是 `.hap`。

> ⚠️ OpenHarmony 自带的默认签名材料签不了商用 HarmonyOS NEXT 手机，
> 必须用你自己的华为开发者证书。

### 2. AGC 创建应用
1. 登录 [AppGallery Connect](https://developer.huawei.com/consumer/cn/service/josp/agc/index.html)
2. 我的应用 → 新建应用
3. **包名必须填 `com.ltyksa.gltuschedule`**（和 `app.json5` 里的 bundleName 逐字一致，填错传不上去）
4. 应用名填 `GLTU 课表`
5. 应用分类建议：**教育 → 学习工具**
6. 上传图标用 `docs/appgallery-icon-216.png`

### 3. 权限说明
AGC 审核会逐条核对权限用途。本应用申请的权限：

| 权限 | 用途 | 是否必须 |
|---|---|---|
| `ohos.permission.INTERNET` | 登录教务系统导入课表、同步节假日 | 必须 |
| `ohos.permission.GET_NETWORK_INFO` | 同步前判断网络，避免空等超时 | 建议 |
| `ohos.permission.READ_PASTEBOARD` | 读取课表分享码 | 建议 |
| `ohos.permission.PUBLISH_AGENT_REMINDER` | 上课提醒 | 必须（核心功能） |
| `ohos.permission.READ_CALENDAR` | 同步课表前清理上次写入的日历条目 | 可选 |
| `ohos.permission.WRITE_CALENDAR` | 把课表写进系统日历 | 可选 |

> 想减少审核阻力，可以**去掉日历那两个权限**（同步到日历是附加功能）。
> 去掉的话要同时删掉设置页的「同步到手机日历」区块，否则点了会报权限错误。
> 这需要改代码，要做告诉我。

### 4. 隐私政策（必做）
AGC 强制要求隐私政策 URL。本应用**全程本地运行、不上传任何用户数据**，
联网只发生在两个地方：
- 登录你学校的教务系统抓课表（数据只存在本机）
- 拉取公开的节假日数据（holiday-cn / timor.tech）

隐私政策里照实写这两点即可。需要一个可公开访问的 URL（GitHub Pages 就行）。

## 五、上架前建议实测的几处

这些**在无设备环境下无法验证**，上架前最好在真机各过一遍：

1. **教务系统导入全流程** —— ArkWeb 抓 HTML → 解析 → 落库。
   特别注意：教务系统页面很大时会不会卡（本轮已把 HTML 解析从 3 遍优化到 1 遍 + 加超时）
2. **服务卡片** —— 三个规格能否在桌面正常显示、每小时刷新是否生效
3. **上课提醒** —— 通知横幅能不能弹（本轮补了通知槽位，之前会落到最低级渠道：无横幅无铃声）
4. **23:30 卡片切明天** —— `updateDuration` 优先级高于 `setFormNextRefreshTime`，
   准点刷新可能不生效，最差晚到下一小时周期
5. **全屏铺满后的底部胶囊** —— 和小白条的距离、滚动收起是否正常
